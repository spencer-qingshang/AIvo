# 逐题解析

**1. A**（大纲 1. 面向对象的基本概念·识记「对象」）
教材原文：「对象是面向对象开发模式的基本成分，是由描述该对象属性的数据以及可以对这些数据施加的所有操作封装在一起构成的统一体。」B 是**类**的定义（「一组具有相同数据结构和相同操作的对象的集合」）；C 是**消息**的定义；D 是**封装**的定义。四个选项分别是对象、类、消息、封装的原文，是本节最典型的四选一干扰题。

**2. B**（大纲 1. 面向对象的基本概念·识记「对象」）
教材原文：「属性一般只能通过执行对象的操作来改变，操作又称为方法，在 C++ 中称为成员函数，它描述了对象执行的功能。」A「数据成员」对应的是属性；C、D 是 C++ 中特定的函数种类，不是「操作」的通用别名。

**3. A**（大纲 1. 面向对象的基本概念·识记「对象、类」）
这是教辅原题，答案 A。教材解析：「类定义可以视为一个具有类似特性与共同行为的对象的模板，可用来产生对象。每个对象都是类的实例，它们都可使用类中提供的函数，一个对象的状态则包含在它的实例变量中。」B、C、D 都把对象说成类内部的某个成分或某种技术，都不是「实例」这层关系。

**4. A**（大纲 1. 面向对象的基本概念·识记「封装」）
教材原文：「封装是面向对象方法的一个重要原则，它把对象的属性和服务结合成一个独立的系统单元，是一种信息隐藏技术，将对象的外部特征（可用的方法）与内部实现细节（属性和方法如何实现）分开，对象的外部特征对其他对象来说是可访问的，而它的内部细节对其他对象是隐蔽的。」B 说的是模块层次结构（第 2 章内容）；C 是继承的机制描述；D 是运算符重载。

**5. A**（大纲 1. 面向对象的基本概念·识记「继承」）
教材原文：「继承是面向对象方法学中的核心概念，它是指一个类的定义中可以派生出另一个类的定义，派生出的类被称作子类，可以自动拥有父类的全部属性和服务。」B 是**多态**的定义；C 是**函数重载**的定义；D 描述的是对象之间通过消息联系，不是继承。

**6. B**（大纲 1. 面向对象的基本概念·识记「多态」）
教材原文：「在面向对象的软件技术中，多态性是指子类对象可以像父类对象那样使用，同样的消息既可以发送给父类对象也可以发送给子类对象。」A、C、D 都是编造的说法：C 中的「多个功能、各自入口」描述的是第 2 章的信息内聚。

**7. B**（大纲 1. 面向对象的基本概念·识记「重载」）
教材原文：「有两种重载，即函数重载和运算符重载。函数重载是指在同一作用域内的若干个参数特征不同的函数可以使用相同的函数名字。运算符重载是指同一个运算符可以对不同类型的操作数施加操作。」A 漏掉了运算符重载；C 说的是「重写/覆盖」的概念，教材未如此表述重载；D 错在「与参数无关」——重载的判据正是**参数特征不同**。

**8. D**（大纲 1. 面向对象的基本概念·识记「对象」中的消息）
教材原文指出，接收对象对消息的处理「可能会改变对象的状态，即改变接收对象的属性，**并发送一个消息给自己或另一个对象**」；消息的定义也强调「**指定某一个对象**」。可见消息正是**发送给另一个对象**的，D 说「只能在两个同类对象之间传递，不能发送给另一个对象」与教材相反。A、B、C 均为教材原文。

**9. B**（大纲 2. 统一建模语言·识记「UML的定义和用途」）
教材原文：「统一建模语言 UML 是一个通用的可视化建模语言，用于对软件进行描述、可视化处理、构造和建立软件系统制品的文档。」A 错，UML 不是编程语言（它不能编译运行）；C 错，UML 不是过程模型；D 错，UML 不是数据库查询语言。

**10. A**（大纲 2. 统一建模语言·识记「UML的定义和用途」）
教材原文：「它可用于对系统的需求分析、设计、浏览、配置、维护和信息控制。」记忆口诀「需设浏配维信」。B、C、D 分别是编译执行、软件生命周期活动、项目管理活动的清单，都不是教材所列 UML 的用途。

**11. B**（大纲 2. 统一建模语言·识记「UML的定义和用途」）
教材原文：「UML 是一种离散的建模语言，不适合对诸如工程和物理学领域中的连续系统建模。它是一个综合的通用建模语言，适合对诸如由计算机软件、固件或数字逻辑构成的离散系统建模。」A 说反；C 错，教材明确指出用户图形界面设计、超大规模集成电路设计、基于规则的人工智能领域「使用专门的语言和工具可能会更适合」；D 说反，UML 正是适合对软件、固件或数字逻辑构成的离散系统建模。

**12. C**（大纲 2. 统一建模语言·领会「用例图的作用及画法」）
这是教辅原题，答案 C。教材解析：「用例图表示使用案例即系统功能与角色（表示提供或接收系统信息的人或系统）间的交互。」干扰项对应关系：A「描述系统的业务」→活动图；B「表示系统中类的构成」→类图；D「表示系统的状态变化」→状态图。这类「图—用途互换」题必须答得又快又准。

**13. A**（大纲 2. 统一建模语言·领会「协作图的作用及画法」）
这是教辅原题，答案 A。教材解析：「时序图体现处理流程，协作图显示对象间处理过程的分布，状态图为对象的各种状态提供了建模方式，部署图显示网络的物理布局和各种组件的位置。」题干中的「处理过程分布」是协作图的专属关键词。

**14. B**（大纲 2. 统一建模语言·领会「时序图的作用及画法」）
教材原文：「时序图只显示对象而不显示类，类表示对象的类型。对象是特定的，时序图不只显示客户，而且显示客户类的对象，如 Joe。」A 说反；C 错，箭头表示的是「角色与对象或对象与对象之间为完成所需功能进行消息传递」，而非模块调用；D 错，物理部署是部署图的内容。

**15. C**（大纲 3. 面向对象的需求分析·识记「类图的作用与规范」）
这是教辅原题，答案 C。教材原文：「类图用于描述系统静态结构，可以自动转换为程序代码。」包图（A）描述子系统分组；组件图（B）描述软件组件及其相关性；部署图（D）描述网络物理布局。只有类图能自动转成程序代码骨架。

**16. A**（大纲 2. 统一建模语言·领会「组件图的作用及画法」）
教材原文：「组件图中有两种组件：执行组件和代码库。」B 中的输入/输出是模块的类型说法；C 中的边界/实体是分析类的种类（且不含控制类，不完整）；D 把构件图的「提供接口／需求接口」错当成组件的种类。

**17. D**（大纲 2. 统一建模语言·领会「部署图的作用及画法」）
教材原文：「部署图显示网络的物理布局和各种组件的位置。」A 是类图；B 是状态图；C 是用例图。四项分别对应类图、状态图、用例图、部署图的用途，属用途互换题。

**18. A**（大纲 3. 面向对象的需求分析·识记「面向对象分析常用的5种图」）
教材原文：「在面向对象的分析中，主要使用以下 5 种类型的 UML 图。活动图：表示一个过程或数据处理中所涉及的活动；用例图：表示一个系统和它所处环境之间的交互；时序图：表示参与者和系统之间及系统各部分之间的交互；类图：表示系统中的对象类及这些类之间的联系；状态图：表示系统是如何响应内部和外部事件的。」B 中的协作图、组件图、部署图**不在**分析常用 5 种图之列；C 同样混入了协作图、组件图、部署图；D 中的**数据流图**是第 2 章结构化方法的工具。

**19. B**（大纲 3. 面向对象的需求分析·领会「基于用例实现的面向对象的建模步骤」）
8 步中的第 2 步是「确定系统的边界，定义系统做什么和不做什么，以及目标系统和其他外部系统的交互，**建立上下文模型**」。A 活动图模型是第 3 步；C 用例模型是第 4 步；D 静态结构模型是第 5 步。

**20. B**（大纲 3. 面向对象的需求分析·领会「基于用例实现的面向对象的建模步骤」）
第 3 步原文：「**了解系统的业务流程，建立活动图模型**。」这一步紧接着第 2 步的上下文模型。A 是第 2 步；C 状态图是第 7 步；D 部署模型根本不在需求建模的 8 步中（属设计阶段）。

**21. D**（大纲 3. 面向对象的需求分析·领会「基于用例实现的面向对象的建模步骤」）
这是教辅原题，答案 D。基于用例实现的面向对象建模步骤为：① 通过与用户沟通了解基本需求；② 确定系统边界，建立上下文模型；③ 了解业务流程，建立活动图模型；④ 从用户与系统交互角度确定功能，建立用例模型；⑤ 识别问题域内的实体对象和类，建立静态结构模型；⑥ 用时序图描述对象间交互；⑦ 用状态图分析对象状态变化，完善类图；⑧ 迭代执行 1)～7)。**部署模型属于设计阶段的产物**，故 D 不属于这 8 步。

**22. B**（大纲 3. 面向对象的需求分析·综合应用「确定系统的范围，建立系统的上下文模型」）
这是教辅原题，答案 B。教材解析：「上下文模型通常表示目标系统与其他外部系统的关系，外部系统可能产生数据供目标系统使用，同时也使用该系统产生的数据。」A 静态模型通常指类图；C 组件模型属设计阶段；D MVC 是设计模式，不是需求模型。

**23. B**（大纲 3. 面向对象的需求分析·识记「活动图的作用与图标」）
教材原文：「项目初期时了解系统内部的业务流程是非常重要的，UML 中最适合描述企业业务流程的工具就是活动图。」用例图描述的是系统**功能**而不是业务流程本身；类图描述静态结构；部署图描述物理布局。

**24. A**（大纲 3. 面向对象的需求分析·识记「活动图的作用与图标」）
教材原文：「活动图本质上是一种流程图，它着重表现一个活动到另一个活动的控制流，是内部处理驱动的流程。」B 把活动图和状态图混为一谈（状态图才是从事件驱动角度描述状态变化）；C 是部署图的用途；D 是类图的用途。

**25. B**（大纲 3. 面向对象的需求分析·识记「用例图的作用与规范」）
教材原文：「根据标准的 UML 定义、执行者与用例之间的关系，**只能够使用关联关系**表示执行者启动用例。」教材用了「只能够」三字，属于"唯一性"考点。A 说可以有多种关系；C 把「包含关系」（用例与用例之间）错当成执行者与用例之间；D 错，执行者代表**系统外**对于系统有影响力的用户或外部系统。

**26. A**（大纲 3. 面向对象的需求分析·识记「用例图的作用与规范」）
教材原文：「用例间的包含关系。一个基本用例里可以包含其他用例具有的行为。执行基本用例时，**每次都必须执行**被包含的用例，被包含的用例**可以单独执行**。」B 错在「选择性地」（有选择地执行是逻辑内聚/可选的味道，不是包含关系）；C 错，被包含的用例可以单独执行；D 错，包含关系用带箭头的虚线并标 `«include»`，与普通关联的实线不同。

**27. A**（大纲 3. 面向对象的需求分析·领会「对用例图的描述」）
教材原文：「与替代流不同的是，替代流往往是**执行者对于流程有不同的指示**，因而将流程导向不同的结束点，而意外处理则通常是**系统发生错误**导致的正常流的意外状况。」B 把两者说反；C、D 均无依据。

**28. B**（大纲 3. 面向对象的需求分析·识记「对象模型中的实体类、边界类、控制类」）
教材原文：「实体类：问题域中的核心类，从客观世界中的实体对象归纳抽象出来，用于**长期保存系统中的信息**，以及提供针对这些信息的相关处理行为。」边界类是从系统与外界交互的对象中抽象出来的连接媒介；控制类用于协调边界类和实体类之间的交互；D「接口类」不在教材的三种类之列。

**29. B**（大纲 3. 面向对象的需求分析·识记「对象模型中的实体类、边界类、控制类」）
教材原文：「边界类：从系统和外界进行交互的对象中归纳、抽象出来的，是系统类的对象和系统外的执行者的连接媒介，**外界的消息只有通过边界类的对象实例才能发送给系统**。」A 实体类用于长期保存信息；C 控制类用于协调边界类和实体类之间的交互。

**30. A**（大纲 3. 面向对象的需求分析·识记「类的组成」；领会「类的筛选」）
这是教辅原题，答案 A。教材解析：「类名是访问类的索引，应当使用含义清晰、用词准确、没有歧义的名字作为类名。注意区分类和属性。」B「员工姓名」、C「员工所属部门」、D「员工身份证号」都是描述员工特征的**属性**，属于「类的筛选」中要排除的「属性」这一类候选。另一道教辅原题与之配对：「适合作为类的属性的是」——答案是「手机型号」（其余三项「学生」「计算机」「服装」都是类）。

**31. A**（大纲 3. 面向对象的需求分析·领会「类之间的关系：泛化关系」）
这是教辅原题，答案 A。教材原文：「泛化关系表达了两个类之间『一般』与『特殊』的关系。泛化的图标为一个由子类指向父类的箭头。」B 聚合是整体-部分关系的一种（部分可独立存在）；C 关联是类与类之间**最基本**的关系，表达结构性关系；D 整体-部分关系是关联的一个特例，表达的是"整体与部分"而非"一般与特殊"。

**32. A**（大纲 3. 面向对象的需求分析·识记「状态图的作用与规范」）
教材原文：「起始状态：在一个状态机或状态机图中，**只能有一个起始状态**，这一点与活动图的起始点是相同的。起始状态用一个**实心的圆形**表示……结束状态：……在一个状态机或状态机图中，**可以有很多结束状态**。」B、C 都错在个数限制；D 把两种图形说反了（起始状态是实心圆，结束状态是牛眼形）。

**33. A**（大纲 4. 面向对象的设计·识记「面向对象软件设计需要完成的工作」）
教材原文：「面向对象软件设计需要完成的工作如下：1）数据/类设计……2）体系结构设计……3）接口设计……4）构件设计。」B 是软件生命周期的宏观阶段；C 是三层架构的分层；D 是**类图建模**的 4 个步骤（属需求分析阶段），不是设计工作。

**34. B**（大纲 4. 面向对象的设计·领会「低耦合」）
教材原文：「对象之间的耦合可分为交互耦合与继承耦合两大类。」对交互耦合的要求是「为使交互耦合尽可能松散」；而「**继承耦合。与交互耦合相反，应该提高继承耦合的程度**」，因为通过继承结合起来的父类和子类「构成了系统中粒度更大的模块……它们彼此之间应该结合得越紧密越好」。这是本章最重要的「反向」考点，A、C、D 均与教材相悖。

**35. A**（大纲 4. 面向对象的设计·领会「高内聚」）
教材原文列出面向对象设计中的 3 种内聚：「操作内聚：一个操作应该完成一个且仅完成一个功能。类内聚：应该使一个类只有一个用途……泛化内聚：设计出的泛化结构应该符合多数人的概念。」故 B 类内聚强调「一个类只有一个用途」；C 泛化内聚强调泛化结构符合多数人的概念、是对领域知识的正确抽取；D 逻辑内聚是**第 2 章**结构化方法中模块内聚的一种，不属于面向对象设计的 3 种内聚。

**36. B**（大纲 4. 面向对象的设计·领会「三层架构」）
教材原文：「通常意义上的三层架构就是将整个业务应用划分为界面层、业务逻辑层和数据访问层。区分层次依据『高内聚低耦合』的思想。」A 是 **MVC 的三个核心部件**（视图、控制器、模型），是最常见的混淆项；C 是网络体系结构的层次名称；D 为编造。

**37. C**（大纲 4. 面向对象的设计·领会「MVC模式」）
这是教辅原题，答案 C。教材解析：「MVC 应用程序被分成 3 个核心部件：视图、控制器、模型。」A 把三个部件说成「视图、数据、操作」；B 描述的是**三层架构**（界面层、业务逻辑层、数据访问层）而不是 MVC；D 为编造。务必把「三层架构」和「MVC 三部件」两组名词分开放。

**38. A**（大纲 3. 面向对象的需求分析·领会「时序图的作用」）
教材原文：「一般来说，时序图的主要任务包括如下几项。1）表达设计人员心中关于将来程序在运行时的对象协作模型。2）验证软件领域模型类图的正确性……3）为程序员提供编码的蓝图。」B 是部署图的内容；C 是体系结构设计的定义；D 是包（包图）的作用。

**39. B**（大纲 3. 面向对象的需求分析·领会「时序图中的对象、消息、生命线、活动棒」）
教材原文：「每个对象生命线上的**狭长矩形**是**活动棒**，在活动棒内的所有消息之间存在清晰的时序关系。」A 生命线是对象下方那条**虚线**；C 事件触发器是**状态图**中标记在迁移上的事件；D 迁移也是状态图的元素（带标签的箭头）。

**40. D**（大纲 4. 面向对象的设计·识记「用户界面设计的黄金规则」）
教材原文：「关于界面设计有以下 3 条黄金规则。1）把控制权交给用户。2）减轻用户的记忆负担。3）保持界面一致。」D 项「尽可能多地使用图形和动画」既不是黄金规则，也与「减轻用户的记忆负担」「保持界面一致」的精神相冲突（过多动画反而分散注意力）。教材对「减轻记忆负担」的具体要求是：减少对短期记忆的要求、建立有意义的默认设置、定义直观的快捷方式、视觉布局基于真实世界的象征、以渐进方式揭示信息。

**41. A**（大纲 4. 面向对象的设计·识记「部署图的作用与规范」）
教材原文：「节点是存在于运行时，并代表一项计算机资源的物理元素。」B 是**构件**的定义（「构件是系统中可以被替换的物理部件，一个构件通常会实现一组特定的接口」）；C、D 分别描述类图的类和状态图的状态。记住构件与节点的分工：「构件是参与系统执行的事物，而节点是执行构件的事物」，节点像服务器，构件像其上运行的软件。

**42. A**（大纲 4. 面向对象的设计·综合应用「通过构件级设计……得到系统的设计类图」）
教材原文：「从分析类转换成设计类需要结合具体的设计模式，如本节前面所提到的 MVC 三层模式，可以得到以下公式：**分析类 + 设计模式 = 设计类**。」B、C 的运算关系与教材相反或颠倒；D 把「设计模式」换成「用例」，虽然用例确实反映了需求并用于识别设计类，但公式本身写的是设计模式。

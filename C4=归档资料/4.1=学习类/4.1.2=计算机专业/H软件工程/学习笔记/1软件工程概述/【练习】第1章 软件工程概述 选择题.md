# 逐题解析

> 解析中标注了该题对应的大纲知识点，便于回查考纲原文。

**1. B**（大纲 1. 软件·识记「软件的定义」）
软件 = 程序 + 数据 + 相关文档的完整集合。A 只提到程序与工具；C 只是「程序」的定义；D 是软件在非计算机专业领域的广义理解，不是软件工程领域的定义。

**2. B**（大纲 1. 软件·识记「软件的定义」）
数据是使程序能正常操纵信息的数据结构。A 说的是运行输出；C 是数据库记录；D 是文档的定义，三者都不等价于大纲所定义的「数据」。

**3. C**（大纲 1. 软件·识记「软件的定义」）
文档是与程序开发、维护和使用有关的图文材料，包括需求分析文档、设计文档、测试文档、维护记录等；接口文档、用户手册属此类。A、D 属「程序」，B 属「数据」。

**4. B**（大纲 1. 软件·识记「软件的特点」）
软件与硬件「磨损」形式不同：软件不会因运行次数增加而物理磨损，但会因环境变化、补丁累积或设计老化而退化。A 说「不会失效」过于绝对；C、D 都是把软件当成硬件。

**5. A**（大纲 1. 软件·识记「软件的特点」）
软件首个版本开发成本高、复制成本低；硬件每增加一件产品都要材料和制造成本。B 生产方式不同；C 软件抽象性更强；D 软件开发成本比硬件制造更难控制。

**6. A**（大纲 1. 软件·识记「软件的特点」）
软件特点包括：生产方式不同、磨损形式不同、个性化细节多需定制、抽象性更强、成本更难控制、功能常涉及机构的组织体制与管理方式等社会因素。B、C 与大纲表述相反；D 与「生产方式不同」矛盾。

**7. B**（大纲 2. 软件工程·识记「软件工程的定义」）
定义原文：软件工程是从管理和技术两方面研究如何更好地开发和维护计算机软件的一门学科。A、C、D 都只覆盖其中一部分。

**8. B**（大纲 2. 软件工程·识记「软件工程的定义」）
软件工程的基本思想是按工程化的原则和方法组织软件开发。

**9. C**（大纲 2. 软件工程·识记「软件工程的研究领域」）
软件工程研究领域包括开发过程的步骤、需求描述、软件设计、编程实现、软件测试、项目管理等。硬件电路设计与制造工艺属于电子/计算机硬件学科，不属于软件工程研究领域。

**10. B**（大纲 2. 软件工程·领会「软件危机面临的问题」）
软件危机用于描述软件开发中遇到的一系列主要问题。A、C、D 都是把「危机」误解为安全事件、淘汰或法律纠纷。

**11. C**（大纲 2. 软件工程·领会「软件危机面临的问题」）
大纲列出的 6 项：缺乏计划性、需求不够充分、缺乏过程规范、成本与进度难以控制、没有质量评测标准和方法、软件难以维护。「缺乏好的算法」不在其中——这是常见干扰项。

**12. A**（大纲 2. 软件工程·领会「软件危机面临的问题」）
A 中三项均为大纲原文表述。B、C 属人员与硬件问题；D 语言种类多不是危机成因。

**13. A**（大纲 2. 软件工程·领会「软件危机面临的问题」）
背景是：硬件技术进步、高级语言出现、应用领域日益广泛，需要开发规模大小不一、功能各异的软件，在大型软件开发中暴露出一系列问题。

**14. B**（大纲 2. 软件工程·领会「软件危机面临的问题」）
典型表现：进度不断延迟、成本难以控制、质量难以保证、维护困难（如 IBM 开发操作系统的例子）。A 说只是个别现象错；C 说已彻底解决错；D 把原因单一化错。

**15. B**（大纲 3. 软件过程·识记「软件过程的定义」）
原文：软件过程是为了获得软件产品，在软件工具的支持下由软件工程师遵循一定的步骤完成的一系列软件工程活动。A、D 说的是时间或编译过程；C 说的是工具。

**16. B**（大纲 3. 软件过程·识记「软件过程模型的定义」）
软件过程模型是对软件过程的模型化（抽象）描述。A、C、D 分别是结构图、组织结构与测试用例，都不是过程模型。

**17. C**（大纲 3. 软件过程·识记「4 种基本活动」）
软件过程包含 4 种基本活动：①软件需求分析 ②软件设计和实现 ③软件测试 ④软件演进。
注意：你提供的大纲图片在「识记」中只逐条写出了前 3 项的活动内容，第 4 项「软件演进」未在图内展开；该词条见《【电子教辅】13005 软件工程-电子教辅（通用版）.pdf》第 6 页「4）软件演进。改进、完善软件的功能以满足用户不断变化的需求。」「软件演进」也正是第 19 题的答案，须重点记住。

**18. D**（大纲 3. 软件过程·识记「4 种基本活动」）
软件市场推广属于商业活动，不属于软件过程的基本活动。A、B、C 均为基本活动的组成部分。

**19. B**（大纲 3. 软件过程·识记「4 种基本活动」）
「软件演进」是软件过程的第 4 种基本活动，指不断根据用户需求对程序进行修改、完善的循环往复过程。A「软件维护」是瀑布模型等过程模型中的阶段名称，与「演进」不同名；C「软件复用」、D「软件调试」都是其他章节的概念，属干扰项。

**20. A**（大纲 3. 软件过程·识记「需求分析阶段的目标」）
原文：通过软件需求分析，完成对软件功能、行为、性能、接口等方面的需求调查、了解，并用规范的软件工程语言对软件需求进行描述，形成软件需求分析文档。B 是设计实现阶段任务；C 是测试阶段目标。

**21. B**（大纲 3. 软件过程·识记「软件实现阶段的任务」）
原文：通过软件设计和实现阶段的活动，设计并实现需求分析阶段定义的功能和性能要求。A 属需求分析；C 属测试；D 属维护。

**22. A**（大纲 3. 软件过程·识记 + 各阶段目标）
测试的目标是确定软件功能的正确性和性能是否符合软件需求分析文档描述的要求。B 说「全部错误全部改正」不现实；C 说「证明没有错误」违背测试原则（测试只能证明有错，不能证明无错）；D 是成本评估。

**23. C**（大纲 3. 软件过程·识记）
C 与大纲原文一致。A 错，维护也是软件过程的活动之一；B 错，软件过程并不要求严格串行，可迭代；D 错，需求分析在前。

**24. B**（大纲 4. 软件过程模型·领会「瀑布模型」）
瀑布模型把软件过程按阶段划分，各阶段自上而下、依次衔接，如同瀑布流水。A、C、D 都不是其划分依据。

**25. B**（大纲 4. 软件过程模型·领会「瀑布模型存在的问题」）
瀑布模型要求早期就确定完整需求，而用户往往难以做到；由于测试在后期，错误发现晚、返工代价大。A、C、D 与事实相反。

**26. B**（大纲 4. 软件过程模型·领会「瀑布模型」）
瀑布模型的特征是阶段顺序推进、文档驱动、阶段评审。A 是原型/敏捷特征；C 是原型模型；D 是螺旋模型。

**27. A**（大纲 4. 软件过程模型·领会「每种模型适合的软件系统」）
瀑布模型适合需求明确、变化少、技术成熟、顺序推进的项目。B、D 适合原型或敏捷；C 适合螺旋模型。

**28. B**（大纲 4. 软件过程模型·领会「原型模型的软件开发过程」）
原型模型先快速构建可运行原型供用户试用，依据反馈修改细化，逐步逼近最终系统。A、C、D 都不是原型模型的过程特征。

**29. B**（大纲 4. 软件过程模型·领会「原型模型存在的问题」）
主要问题：用户可能把原型当作最终产品；原型以快速实现为目标，内部质量（性能、可靠性、可维护性）往往不达标，若直接交付会留下隐患。A、D 与事实相反；C 恰恰是原型模型的适用场景。

**30. B**（大纲 4. 软件过程模型·领会「螺旋模型的特点」）
螺旋模型把开发组织为多轮螺旋，每轮都做风险分析，这是它与瀑布、原型最本质的区别。A、C、D 与螺旋模型特征不符。

**31. B**（大纲 4. 软件过程模型·领会「按螺旋模型进行软件开发的过程」）
每轮螺旋的活动：制定计划、风险分析、实施工程、客户评估。A 是瀑布/一般开发阶段；C 是 PDCA 循环；D 是工程项目建设流程。

**32. B**（大纲 4. 软件过程模型·领会「每种模型适合的软件系统」）
螺旋模型因强调风险分析，适合大型、风险高的项目。A 适合瀑布；C、D 不是软件工程的正常场景。

**33. C**（大纲 4. 软件过程模型·领会「统一过程模型」）
统一过程模型包括 5 个工作阶段。

**34. B**（大纲 4. 软件过程模型·领会「5 个工作阶段及每个阶段的工作内容」）
统一过程模型的 5 个阶段为初始、细化、构建、移交、生产。A 是通用开发阶段；C 是螺旋模型每轮活动；D 是常见工程阶段划分。

**35. B**（大纲 4. 软件过程模型·领会「统一过程模型」）
UP 的三大特点：用例驱动、以体系结构为中心、迭代与增量。A、C、D 均与 UP 的定义不符。

**36. B**（大纲 5. 敏捷开发·领会「敏捷开发的基本思想、过程和工具」）
敏捷强调短周期迭代、持续交付可运行软件、快速响应变化、重视人与协作。A 是传统重量级过程的特征；C 是瀑布式的做法；D 与自组织团队相悖。

**37. C**（大纲 5. 敏捷开发·领会「敏捷开发的基本思想」）
「一次性冻结需求」与敏捷「拥抱变化」的核心相悖。A、B、D 都是敏捷的典型特征。

**38. B**（大纲 5. 敏捷开发·领会「Scrum 模型的团队」）
Scrum 的三种角色：产品负责人、Scrum Master、开发团队。A、C、D 是传统项目或职能型分工。

**39. A**（大纲 5. 敏捷开发·领会「Scrum 模型的冲刺会议」）
Scrum 的会议包括冲刺计划会议、每日站会、冲刺评审会议、冲刺回顾会议。B、C、D 都不是 Scrum 的标准会议设置。

**40. B**（大纲 5. 敏捷开发·领会「XP 模型的关键任务」）
XP 的核心实践包括计划游戏、小型发布、隐喻、简单设计、测试先行、重构、结对编程、集体代码所有制、持续集成、每周 40 小时、现场客户、编码标准等。A 属项目管理/风险与计划；C 属结构化分析工具；D 属测试层次划分。

**41. A**（大纲 5. 敏捷开发·领会「Scrum 模型和 XP 模型的软件开发过程」）
两者同属敏捷：Scrum 偏重项目管理与团队协作框架（角色、会议、冲刺），XP 偏重工程实践（测试先行、结对编程、重构、持续集成）。B 错，二者不是瀑布变体；C 把两者特征说反；D 与敏捷「拥抱变化」矛盾。
